# 6. 安全边界

> 规则条目在根 `AGENTS.md` 的「硬约束」；本文件只解释理由与边界案例，不重复规则。

## 6.1 路径边界

agent 的工作范围是整个 monorepo，但读取范围不是。项目外的文件可能包含其他项目的配置、用户的密钥或与本任务无关的个人数据；一次“顺手看看”就可能把这些内容带进上下文、日志或提交。

- 外部路径的授权是**单次、具体**的：用户同意读取 `/some/path/config.json`，不等于同意遍历该目录，也不等于同意后续命令继续访问。
- 授权不会因为“上次也是这个目录”而延续；每次需要跨目录操作时重新确认。
- 符号链接按目标路径判断，不按链接所在位置判断。
- 全局开发工具（`git`、`go`、`cargo`、`xcodebuild`、包管理器等）可以正常使用；读取它们的缓存内容不属于工具使用。

## 6.2 临时产物

构建中间文件、截图、日志、trace、测试 fixture 草稿与 smoke-test 输出必须写入目标应用的 `.tmp/`，并且该目录已被 `.gitignore` 忽略。

原因是这些产物有三个风险：

1. **误提交**：截图和日志常包含路径、用户名、token 或页面内容；放在项目内且被忽略，才能在 review 时被明确排除。
2. **不可复现**：系统临时目录会被清理，ACL 与挂载点也不同；CI 与本地的结果无法对齐。
3. **范围蔓延**：先写 `/tmp` 再复制回项目，会让“产物属于哪个任务”变得不可追踪。

如果某个产物确实只能写到项目外，先说明具体路径、用途和操作，等待明确授权；不要先写再解释。工具自身的标准缓存不受此限制。

## 6.3 凭据与外部操作

- 不读取、不复制、不打印 `.env`、密钥、token、Cookie、认证 URL 或页面内容；诊断输出必须脱敏。
- `i18n-studio` 的 `SESSION_SECRET` 在构建期校验非空且非默认值；CI 使用非默认占位值，但不得把真实值写入仓库或文档。
- `go/cmd/artusx-api` 的 `WEBHOOK_AUTH_TOKEN`、`BOT_AUTH_TOKEN` 与 Telegram channel 配置只从环境变量或本地 `.env` 读取；`.env` 不提交。
- `dsh-telegram` 的发布凭据只在发布环境使用；`prepublishOnly` 的运行不代表凭据可以进入日志。

以下操作需要用户明确指示，不能由“完成定义”自动推导出来：

- 打 tag、创建 GitHub Release、公开 Draft Prerelease。
- 推送镜像、`wrangler deploy`、`npm publish`。
- 写入外部仓库、修改远端基础设施或密钥。
- 安装全局工具或改变本机工具链版本。

`gitleaks` 在 push / PR 时扫描密钥；它只能兜底，不能替代上面这些约束。

## 6.4 边界案例

| 场景 | 处理 |
| --- | --- |
| 用户要求参考另一个项目的实现 | 先确认具体路径与读取范围；只取需要的文件，不遍历 |
| 调试需要查看系统日志 | 说明路径与用途并等待授权；优先让工具输出诊断而不是直接读文件 |
| 截图包含真实账号或页面内容 | 写入 `.tmp/`，脱敏后再引用；不得作为公开资产提交 |
| CI 需要占位密钥 | 使用明显的非默认占位值，并在 workflow 注释说明用途 |
| 发现仓库中已有明文密钥 | 停止扩散，报告位置，不复制内容；按用户指示处理 |
