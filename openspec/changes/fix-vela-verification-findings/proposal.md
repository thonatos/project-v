# Proposal

## Why

重构后的双机与真机验收暴露了 8 处跨端不一致和两个功能性缺陷：iOS 首屏的状态查询会阻塞在节点启动上，导致设备和服务的出现明显延迟；macOS 的诊断信息又一直上报写死的协议版本 `2`，而真实值是 `1`。与此同时，两个客户端在账户、设置、日志、设备四个页面使用了不同的词表、区块结构与控件，用户需要在两套界面之间重新学习。

这些问题都不是协议或数据模型的缺陷，可以在不改变控制协议的前提下集中修正，越早处理越能避免两端继续各自演化。

## What Changes

- **macOS 版本信息**：账户/设置页补「关于」（版本、控制协议）；协议号改为从 `CoreBridge.protocolVersion()` 读取，删除写死的 `2`，诊断信息同步使用真实值。
- **iOS 启动不阻塞**：节点启动改为后台进行；节点尚未运行时 `status` 立即返回 `connecting`，首屏可渲染，连上后由轮询补齐设备与清单。不再让 `sync.Once` 阻塞状态查询。
- **iOS 签名提示**：根据描述文件的实际到期时间生成说明；只有剩余 ≤ 7 天才提示续签，不再固定写「免费签名 7 天」。
- **账户页统一（A 方案）**：两端都使用「头像 + 账户名」身份头；账户只在身份头出现一次；「私人连接」区块只保留「状态 + Tailnet」；区块顺序统一为 身份头 → 私人连接 → 这台设备的身份 → 开发签名（仅 iOS）→ 注销。
- **设置页统一**：区块顺序为 外观 → 共享（仅 macOS）→ 通用（仅 macOS）→ 隐私（Gravatar，两端）→ 诊断（详细日志 + 复制诊断 + 摘要）→ 关于；外观与日志级别统一使用分段选择；外观文案统一为「跟随系统 / 浅色 / 深色」。
- **日志页统一**：两端都使用分段选择级别（同标签、同计数）；动作统一为「刷新 + 复制日志」；空态文案统一。
- **设备页统一**：行结构对齐 iOS（图标块 + 名称 + 「状态 · N 个服务」+ 状态点）；地址移入设备详情页；术语统一为「这台 Mac/iPhone」「其他设备」「添加设备」。
- **macOS 新增桌面 atoms**：`Avatar`、`IconTile`、`Dot`、`Segmented`，按桌面密度实现，不与 iOS 共用组件；Core 的 macOS 入口打开 `Avatar`，使 `status` 在启用 Gravatar 时返回头像地址。
- **共享版本常量**：`shared/ui` 提供唯一的 `APP_VERSION`，两端「关于」使用它，并由测试校验与两个 `nsh.json` 的 `version` 一致。

## Capabilities

### New Capabilities

- `vela-ui-consistency`：定义两个客户端共享的界面契约——单一信息呈现、账户页信息架构、跨端词表（私人连接 / Tailnet / Mac）、同类选择控件、版本与协议展示、设备行结构、设置与日志页的信息架构。

### Modified Capabilities

- `vela-ios-access`：新增「启动不阻塞」要求（首屏在节点启动期间保持可用并显示连接中），以及「开发签名有效期表述」要求（按实际到期时间生成提示）。

## Impact

- **UI**：`macos/ui` 新增 4 个 atom 并调整账户、设置、日志、设备四页；`ios/ui` 调整账户、设置、日志、设备页的区块与词表。
- **Core**：`network.Embedded` 增加异步启动与运行状态探测；`internal/core` 的 `Status` / `AuthStatus` 在节点未运行时返回 `connecting` 而不阻塞；`cmd/vela-core` 打开 avatar 选项。
- **共享层**：新增 `APP_VERSION`；`shared/ui` 的日志级别与外观选项成为两端共同来源。
- **测试**：两端的结构测试需同步更新；新增 Go 的非阻塞状态测试、iOS 首屏行为测试、签名文案单测、版本一致性测试。
- **兼容性**：控制协议 v1、`config.json`、数据目录与 bundle id 不变；无数据迁移。
- **非目标**：不合并两端的 atoms；不改变 iOS 的只读能力边界；不使用截图或视觉基线作为验收方式。

## Rollback Plan

- 按页面/模块分提交：版本信息、启动非阻塞、签名文案、账户页、设置页、日志页、设备页、桌面 atoms 各自独立，可单独 revert。
- Core 的非阻塞状态改动附带行为测试；若出现状态误报，可只回退 `network` 与 `internal/core` 的提交，UI 保持可用。
- 新增 atom 只被新页面使用，回退页面改动不要求回退 atom。
