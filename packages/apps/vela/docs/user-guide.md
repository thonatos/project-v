# Vela 用户指南

Vela 是一个 macOS 控制台：既可以把这台 Mac 上已运行的本地服务共享给自己的其他设备，也可以访问其他 Mac 共享出来的服务。它不区分服务端与客户端模式。

## 界面结构

窗口使用 macOS 系统标题栏。左侧是固定的图标导航：

| 图标     | 页面 | 快捷键 |
| -------- | ---- | ------ |
| 显示器   | 设备 | `⌘1`   |
| 双向箭头 | 转发 | `⌘2`   |
| 列表     | 日志 | `⌘3`   |
| 人像     | 账户 | `⌘4`   |
| 齿轮     | 设置 | `⌘,`   |

设备与转发在上，日志、账户与设置是应用级页面，位于导航底部。窗口是固定尺寸的竖向工具窗，不可缩放。

设备与服务都采用“列表 → 详情”：在列表中点击条目进入详情，详情左上角的面包屑返回上一级（`⌘[` 或 `Esc`）。

## 首次连接

1. 启动 `Vela.app`。
2. 打开「账户」页（`⌘4`），选择「连接 Tailscale」，在系统浏览器完成登录。
3. 返回 Vela，状态变为「在线」。

Vela 使用进程内 userspace 网络，不安装系统 VPN，不修改代理、DNS 或路由。

## 账户

「账户」页集中登录态与身份信息：

- **私人连接**：连接状态、登录账户、所属 tailnet。
- **这台 Mac 的身份**：设备名称（可修改，会同步到 Tailscale 节点）、MagicDNS 名称、Tailscale 地址。
- **登录**：重新检查连接，或注销。注销会移除本机保存的身份，共享与转发随之停止。

设置页只保留偏好，不再混入登录态信息。

## 共享这台 Mac

1. 在设备页点击「这台 Mac」。
2. 打开「共享这台 Mac」。
3. 在「本地服务」中点击「添加服务」。

设备名称与地址在「账户」页查看和修改。

添加服务时，服务类型按协议分为两组，选项直接列在表单里：

| 分组     | 预设        | 默认地址                          |
| -------- | ----------- | --------------------------------- |
| Web 服务 | OpenCode    | `http://127.0.0.1:49374/api/info` |
|          | DSH         | `http://127.0.0.1:3080/`          |
|          | ComfyUI     | `http://127.0.0.1:8188/`          |
|          | 自定义 HTTP | 自行填写                          |
| TCP 服务 | SSH         | `127.0.0.1:22`                    |
|          | Redis       | `127.0.0.1:6379`                  |
|          | MySQL       | `127.0.0.1:3306`                  |
|          | PostgreSQL  | `127.0.0.1:5432`                  |
|          | 自定义 TCP  | 自行填写                          |

已添加过的 OpenCode 或 DSH 会显示为不可选；其他预设可以添加多次。

新安装不会预置任何服务，需要共享什么就添加什么。两类服务都只接受 `localhost`、`127.0.0.1` 或 `::1` 上的地址：Web 服务填写完整 HTTP 地址，TCP 服务填写 `地址:端口`。

每个服务行右侧的开关单独控制是否共享。首次开启时会提示风险：Web 服务可以运行命令并修改这台 Mac 上的文件；SSH 可以获得这台 Mac 的命令行。只应共享给你信任的自己的设备。Vela 只代理已经在运行的服务，不会启动、停止或配置它们。

服务行右侧的「更多操作」可以编辑或删除服务。

### TCP 服务的可用性

Vela 不会连接 TCP 服务来检查它是否在线，只检查这个端口有没有程序在监听。原因是很多 TCP 服务会把探测当成失败的登录：SSH 会记录非法握手，MySQL 默认在 100 次失败握手后封禁来源地址，按 Vela 每 10 秒检查一次计算，约 17 分钟就会把本机封掉。所以 TCP 服务显示「可用」只表示端口在监听，不代表认证一定能通过。

### SSH 需要先开启远程登录

共享 SSH 前，先在「系统设置 › 通用 › 共享」中开启「远程登录」。Vela 不会替你开启它。SSH 显示「未在监听」时，通常就是远程登录没有开启。

Vela 不参与 SSH 认证，密钥和密码仍由 `sshd` 校验。

### ComfyUI 的局域网暴露

ComfyUI 没有自己的登录机制。如果它用 `--listen 0.0.0.0` 启动，同一局域网里的任何人已经可以直接访问它，这与 Vela 无关。Vela 只连接它的 loopback 地址，不会扩大这个暴露面，但也无法收窄。如果你只想通过 Vela 访问，请改用 `--listen 127.0.0.1` 启动 ComfyUI。

## 添加其他设备

1. 在设备页的「其他设备」区域点击「添加设备」，或使用 `⌘N`。
2. 从 Tailnet 设备列表中选择一台，或手动输入完整私人名称，例如 `home-mac.example.ts.net`。
3. 点击「验证并添加」。

列表支持方向键选择、`Enter` 提交。已添加的设备会显示为「已添加」且不可重复选择。Vela 只保存在线、已授权且协议兼容的设备。

设备列表显示每台设备的 Tailscale IP。删除设备只移除本机记录，不影响那台 Mac 上的 Vela。

## 转发远端服务

Vela 不内置浏览器。它把远端服务接到本机一个固定地址上，你用自己的浏览器访问：

```text
浏览器 → http://opencode-home-mac.localhost:47850 → Vela → 远端 Mac 上的服务
```

1. 在设备页点击目标设备进入详情。
2. 在「可用服务」中点击「开始转发」。
3. Web 服务会在 Vela 建立链路后自动在默认浏览器中打开；TCP 服务没有页面，Vela 改为显示连接命令。

转发是长期开关，不是一次性打开。开启后地址长期有效，切换页面或关闭浏览器标签都不会断开；只有点击「停止转发」或正式退出 Vela 才释放。

「转发」页面列出所有转发，每条提供：

- **在浏览器中打开**：仅 Web 服务，再次打开该地址。
- **复制地址**（图标按钮）：Web 服务复制完整地址；TCP 服务复制连接命令。
- **停止转发**（图标按钮）：释放该映射。

每个「设备 + 服务」的地址固定不变，包括重启 Vela 之后，所以浏览器书签和客户端配置长期可用。

### 连接 TCP 服务

TCP 转发显示的是可以直接运行的命令，端口为 Vela 分配的固定本机端口：

| 服务       | 命令示例                                                   |
| ---------- | ---------------------------------------------------------- |
| SSH        | `ssh -p 47901 <user>@ssh-home-mac.localhost`               |
| Redis      | `redis-cli -h redis-home-mac.localhost -p 47902`           |
| MySQL      | `mysql -h 127.0.0.1 -P 47903 -u <user> -p`                 |
| PostgreSQL | `psql -h postgresql-home-mac.localhost -p 47904 -U <user>` |
| 自定义 TCP | `custom-home-mac.localhost:47905`                          |

MySQL 使用 `127.0.0.1` 而不是 `.localhost` 主机名：`mysql` 客户端遇到 `localhost` 一类的名称时会改走 Unix socket，连不到转发端口。

因为端口固定，可以在 `~/.ssh/config` 里写一条长期有效的配置：

```text
Host home-mac
    HostName ssh-home-mac.localhost
    Port 47901
    User <user>
```

之后直接运行 `ssh home-mac` 即可。前提是 Vela 正在运行且这条转发处于「转发中」。

地址使用 `<服务>-<设备>.localhost` 形式而不是裸 `127.0.0.1`，因为 Cookie 只按主机名隔离、不区分端口。这样两台 Mac 上的 OpenCode 各有自己的登录态，不会互相覆盖；浏览器的密码管理、扩展、开发者工具和下载也都照常可用。这个域名由标准保证解析到本机，不需要修改 `/etc/hosts` 或安装任何组件。

转发地址只监听本机 loopback，不对局域网或公网开放。但需要知道：本机其他进程和浏览器扩展也能访问它，暴露面与「在本机直接运行该服务」相同；服务自身的登录与 token 校验全部保留。

## OpenCode 与 DSH

OpenCode 首次转发时使用它自己的配对页面，配对后的 Cookie 由浏览器按该地址保存。

DSH 保留自己的 token/Cookie 与 Host/Origin 检查。DSH 的登录链接只在共享 DSH 的那台 Mac 上设置：编辑 DSH 服务时填写「DSH 输出日志」，即 `dsh --profile web` 的标准输出文件（例如 launchd 的 `StandardOutPath`）。Vela 每次被询问清单时读取其中最新一行 `dsh web: http://127.0.0.1:<端口>/?token=…`，把 `/?token=…` 作为该服务的打开路径发给已授权设备；DSH 重启换了 token 也会自动跟上。

转发 DSH 的设备不需要知道 token，打开转发时会先拉取最新的打开路径，浏览器用它换得 DSH 自己的登录 Cookie。不填日志时，转发直接打开 DSH，需要该浏览器已有有效 Cookie。

Vela 不把 token 写入 `config.json`、日志或诊断；但任何通过 Vela 授权的设备都能拿到它，等同于获得 DSH 的登录权限。只在共享给你自己的设备时填写。

出现 authority 拒绝时，按提示配置 DSH 信任的地址，不要关闭 DSH 的认证或来源检查。详见 `sharing.md`。

## 外观与调试

设置页可以选择界面外观：跟随系统、浅色、深色。选择立即生效并在下次启动时恢复。

「调试」区域默认关闭，仅用于排查问题，不改变共享或访问行为：

- **性能 HUD**：显示帧率与渲染开销。
- **详细日志**：记录更多运行细节。

## 查看运行状态

- **设备详情**的「连接活动」显示到该设备的转发映射与活跃连接数。
- **日志页面**按时间显示连接、认证、共享、映射与代理事件，可手动刷新；打开这两个页面时会自动刷新。

日志与诊断只保留运行事件，不包含认证 URL、token、Cookie、凭据或页面内容。

## 退出语义

- 红色关闭按钮或 `⌘W`：隐藏窗口，私人连接、共享与转发继续运行。
- 点击 Dock 图标：恢复同一窗口，不重启 Core。
- `⌘Q`、应用菜单「退出 Vela」或 Dock「退出」：先停止接入与转发，再关闭私人连接并退出。退出后浏览器中的转发地址不再可用。

Core 意外退出时会自动重启，无需重启应用。

## 故障排查

| 现象                                             | 处理                                                                                                                              |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| 状态显示「需要连接」                             | Tailscale 身份失效，在「账户」页重新连接                                                                                          |
| 在 Tailscale 后台删除了这台 Mac，Vela 仍显示在线 | 在「账户」页点「重新检查」。运行中的设备被删除时 Tailscale 不会通知它，重新检查会让它向控制平面重新登录，几秒内即显示「需要连接」 |
| Web 服务显示「不可用」                           | 确认该 loopback 地址正在监听，再点「重新检查」                                                                                    |
| TCP 服务显示「未在监听」                         | 确认服务已启动并监听该端口；SSH 还需开启「远程登录」                                                                              |
| `mysql` 连不上转发端口                           | 主机名改用 `127.0.0.1`，不要用 `localhost` 或 `.localhost` 名称                                                                   |
| 设备显示「离线」                                 | 确认那台 Mac 已启动 Vela 且未睡眠                                                                                                 |
| 提示「需要更新 Vela」                            | 两台设备的协议版本不兼容，更新到同一版本                                                                                          |
| 转发后要求重新登录                               | 确认 Vela 为最新版本；旧版本使用随机端口会导致登录态失效                                                                          |
| 浏览器打不开转发地址                             | 确认该条转发仍显示「转发中」，必要时停止后重新开始转发                                                                            |
| DSH trusted-host 错误                            | 参见 `sharing.md`                                                                                                                 |

设置页的「诊断」区域默认显示协议版本、连接状态、共享与其他设备的脱敏摘要，「复制诊断」复制同样范围的内容。两者都不包含认证 URL、凭据、Cookie 或页面内容。

## 卸载与回滚

1. 使用 `⌘Q` 正式退出 Vela。
2. 删除 `Vela.app`。
3. 如需撤销设备身份，删除 `~/Library/Application Support/Vela/network/`，并在 Tailscale 管理页面撤销对应设备。
4. 如需清除全部本地状态，删除 `~/Library/Application Support/Vela/` 和 `~/Library/Logs/Vela/`。

卸载不会删除或修改 OpenCode、DSH、代码仓库或系统网络配置，也不会改动浏览器设置。
